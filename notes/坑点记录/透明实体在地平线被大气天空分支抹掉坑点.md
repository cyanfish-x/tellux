# 透明实体在地平线被大气天空分支抹掉坑点

本文记录拉伸多边形（及一切绝对高透明实体：面 / 线 / 点）在相机低角度平视时"在地平线处被裁剪"的排查结论。核心经验：**透明实体不写深度，大气的天空分支会把背景为天空的像素（深度仍为远平面 1.0）整体重画成天空、忽略 inputColor**——实体若排在大气之前，其剪影到天空的部分就被抹掉。修复是让实体 OIT 排在大气之后。

这是 [Symbol 锚点遮挡与大气失效坑点](./Symbol锚点遮挡与大气失效的effects链深度坑点.md) 坑 2 的直接后续：那次把实体 OIT 改成 `needsSwap=false` 并定在"大气之前"，解决了 OIT swap 破坏大气深度绑定的问题，但留下了"实体排在大气前又因其不写深度而被天空分支吃掉"的新坑。

## 现象

`examples/entities.ts` 里的 `block-extruded`（粉色拉伸多边形，底面抬升 50m、拉伸 300m）：

- 正常俯视 / 斜视时完整可见。
- 相机压低到接近地面、平视地平线时，多边形**在地平线以上（背景是天空）的部分整体消失**，以下（背景是地形）部分正常——分界线正好是地平线。
- 不是整个多边形消失（排除 frustum 剔除），而是按"背景是天空还是地形"的边界裁切。

## 容易误判的方向

1. **以为是视锥剔除（frustum culling）**。

   多边形用的是 `THREE.ExtrudeGeometry`，其 `boundingSphere` 由位置属性算出，已包含拉伸高度；`frame` 矩阵只有旋转+平移无缩放。three 的剔除走 `geometry.boundingSphere.applyMatrix4(matrixWorld)`，是正确的。若是剔除，应该是整块多边形在某一帧瞬间消失，不会"按地平线裁切"。排除。

2. **以为是远平面（far plane）裁剪**。

   `constants.ts` 里 `near:10, far:1e6`。地平线（相机 2km 高）在 ~160km 处，远小于 1e6，不会触发远裁。排除。

3. **以为是深度精度 / z-fighting**。

   near=10/far=1e6 的标准非线性深度在 5km 处视空间精度 ~0.15m、50km 处 ~15m，多边形抬了 50m 都够用。z-fighting 的症状是闪烁，不是稳定裁切。排除。

4. **以为是 EntityRenderManager 的 OIT 深度 discard 误杀**。

   OIT 派生材质里有 `if (gl_FragCoord.z > sceneDepth + 1e-6) discard;`。但：
   - 多边形背景是天空时，`sceneDepth`（清空值）= 1.0，而 `gl_FragCoord.z`（多边形）≈0.99x < 1.0 → **不 discard**。
   - 背景是地形时，地形比多边形远 → `sceneDepth` > `gl_FragCoord.z` → 也不 discard。

   所以 OIT discard 两边都不会触发，不是它。排除。（但这一步的推导正好把矛头引向"读到的 sceneDepth 是什么"——见根因。）

## 真实根因

### 大气的天空分支无条件重画

`@takram/three-atmosphere` 的 `AerialPerspectiveEffect` 片元着色器（`aerialPerspectiveEffect.frag:296-318`）：

```glsl
float depth = readDepthValue(depthBuffer, uv);
if (depth >= 1.0 - 1e-8) {
  #ifdef SKY
  outputColor.rgb = getSkyRadiance(...);   // 画天空
  outputColor.a = 1.0;
  #else
  outputColor = inputColor;
  #endif
  return;                                   // 直接返回，不再处理 inputColor
}
depth = reverseLogDepth(depth, cameraNear, cameraFar);
// ... 否则按真实几何深度做 transmittance / inscatter / 光照
```

即：**读到深度 ≥ 远平面（1.0）的像素，直接用天空辐射度覆盖，完全忽略 inputColor**（inputColor 里可能已合成了实体）。

### `reverseLogDepth` 在本项目是恒等

`@takram/three-geospatial` 的 `depth.glsl:13-22`：

```glsl
float reverseLogDepth(const float depth, const float near, const float far) {
  #if defined(USE_LOGDEPTHBUF) || defined(USE_LOGARITHMIC_DEPTH_BUFFER)
  // ... 对数深度反解
  #else
  return depth;   // 未开对数深度时恒等返回
  #endif
}
```

`RendererAdapter.ts` 创建 renderer 时**没有**开 `logarithmicDepthBuffer`，所以深度缓冲是标准 `[0,1]`，远平面=1.0，`reverseLogDepth` 是恒等。天空分支的 `depth >= 1.0 - 1e-8` 判定成立。

### 透明实体不写深度 + 排在大气之前

`PolygonGraphic.ts` 拉伸体材质：

```ts
new THREE.MeshBasicMaterial({
  color: resolveColor(options.color),
  transparent: true,
  depthWrite: false,   // ← 从不写深度
  side: THREE.DoubleSide
})
```

`PostProcessingManager.syncEffects` 原来的 pass 顺序：

```
normalAdapter
entityRenderer (实体 OIT)      ← 排在大气之前
groundClampPass
atmosphereAdapter (空气透视)   ← 读 readBuffer 的深度纹理
symbolOcclusionPass
smaa / dithering
```

实体 OIT（`EntityRenderManager`）只把实体颜色 alpha 混合进 `readBuffer`（成图），**深度缓冲里始终没有多边形**（OIT 派生材质也是 `depthWrite:false`，且 OIT 自己的 target 与场景深度无关）。

于是大气 pass 读场景深度时，多边形像素位置读到的还是**背景的深度**：

- 多边形剪影到**天空**：背景深度 = 清空值 1.0 → 命中天空分支 → 被天空重画 → **抹掉**。
- 多边形剪影到**地形**：背景深度 < 1.0 → 走 transmittance/inscatter 分支 → `inputColor` 被保留并按地形深度加雾 → **保留**。

边界就是地平线 → "在地平线处被裁剪"。

### 为什么贴地实体不中招

`GroundClampPass` 的贴地多边形 / 折线永远贴着地形表面，从不剪影到天空，背景深度恒 < 1.0，走不到天空分支。所以本坑只影响**绝对高（非贴地）透明实体**：拉伸多边形、普通面 / 线 / 点。

## 修复：实体 OIT 移到大氣之后

权衡两条路：

- **A（采纳）**：把实体 OIT 移到大氣之后。实体始终清晰、不再被天空抹掉，代价是极远处实体不再随距离雾化（典型几 km 距离几乎无感，且与 Cesium / symbol 标注一致）。
- **B（未采纳）**：实体仍在大气前，但在 OIT 阶段把实体深度写进场景深度缓冲，让大氣用真实实体深度。保留雾化，但需为所有实体类型（含自定义 shader 的线 / 符号）捕获最近深度并在 composite 写 `gl_FragDepth`，在脆弱的 buffer 管线里复杂且风险高。

两处改动：

### 1. `PostProcessingManager.syncEffects` 调整 pass 顺序

```ts
if (shouldRenderAtmosphere) nextEffects.push(this.normalAdapter)
if (this.groundClampPass)   nextEffects.push(this.groundClampPass)
if (shouldRenderClouds)     nextEffects.push(this.cloudAtmosphereAdapter)
else if (shouldRenderAtmosphere) nextEffects.push(this.atmosphereAdapter)
if (this.entityRenderer)    nextEffects.push(this.entityRenderer)   // ← 移到大氣之后
if (this.symbolOcclusionPass) nextEffects.push(this.symbolOcclusionPass)
```

### 2. `EntityRenderManager.render` 两侧探测场景深度

实体排到大氣之后会踩到一个连锁问题：大气 EffectPass `needsSwap=true`，swap 后 `readBuffer` 变成**无深度的 targetB**（深度纹理只挂在 targetA 上）。原代码只查 `readBuffer.depthTexture`，swap 后查不到就 no-op → 透明实体整帧消失。改为 read/write 两侧探测（同 `GroundClampPass` / `SymbolOcclusionPass` 的既有模式）：

```ts
const depthTexture = readBuffer.depthTexture ?? writeBuffer.depthTexture ?? null
if (this.mode !== 'weighted-oit' || !depthTexture || !this.hasTransparentRenderableEntities()) {
  this.needsSwap = false
  this.options.root.visible = true
  return
}
```

颜色仍就地叠加到 `readBuffer`（成图），`needsSwap` 恒 false。OIT 深度 discard 用的是 targetA 的场景深度（地形），能正确遮挡被山体挡住的实体，无 feedback loop（读 targetA 深度、写 targetB 颜色，互不交叉）。

> 行为变化：所有绝对高透明实体（面 / 线 / 点）不再随距离雾化、保持清晰。这同时修掉了地平线裁剪；symbol 标注本就在大气之后，现在所有实体视觉一致。贴地实体不受影响，仍在大气前。

## 维护准则

- **绝对高透明实体必须排在大气 pass 之后**。任何把 `entityRenderer` 移回大气之前的改动都会让本坑复发（地平线裁剪）。这条已写入自动记忆 `transparent-entities-after-atmosphere`。
- 实体不写深度（`depthWrite:false`）是 OIT 正确性的要求（要累加所有透明层），不要为"想让大气用到实体深度"而给实体材质开 `depthWrite`——会破坏 OIT 累加，且派生材质里会被强制设回 false。
- 深度纹理只挂在 targetA 上，任何排在 swap pass（大气 EffectPass）之后的、需要场景深度的 pass 都必须 `readBuffer.depthTexture ?? writeBuffer.depthTexture` 两侧探测，不能只查一侧。
- 相关坑见 [Symbol 锚点遮挡与大气失效坑点](./Symbol锚点遮挡与大气失效的effects链深度坑点.md)：那条确立了"大氣之前的 pass 不得 swap、深度始终保持在 read 侧 targetA"的原则；本条说明"实体这一类不写深度的 pass 索性排到大氣之后"。两者互补。
- 如果未来要让实体重新参与距离雾化（方案 B），需自行渲染实体最近深度（各实体类型含自定义 shader 的线/符号都要覆盖）并在 composite 写 `gl_FragDepth`，且注意未开对数深度（`gl_FragDepth` 是标准 window 深度）。
