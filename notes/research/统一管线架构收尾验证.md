# 统一管线架构收尾验证

> 2026-09-13，以检查点 `38eb10a` 为基线。架构收尾完成：旧调度与隐式深度来源已移除，渲染回归及工程检查通过，证据已归档。点云补测期间的天地图 429 外部请求失败单独记录如下。云穿插继续暂缓。

## 调度与资源归属

- `PostProcessingManager.renderFrame` 统一准备实体与标注、主绘制、最终输出后的标注及 finally 恢复。Viewer 的 WebGL 主路径只调用一次；WebGPU 保持原路径。
- `SceneFrameResources` 在不透明阶段完成后发布目标、深度、像素尺寸，供统一透明、贴地分类、EDL、标注和 EffectPassAdapter 使用。缺失、跨帧或尺寸失效时抛出合同错误；不从 read/write 两侧猜深度，不释放借用目标。
- 实体仅保留显式完整范围与分段范围绘制，均由统一透明阶段调用。旧实体 effects pass、`composedByPipeline` 和标注链内深度捕获已移除；entity-only 不漏绘，直接在当前颜色上执行一次 OIT，无分段目标和颜色复制。
- 贴地分类和 EDL 按被采样纹理与目标附件的身份判断冲突，保留必要中转和拷回。这里的附件检查不是选取深度来源；不更改原深度或颜色算法。
- 不透明目标归 Three.js 输出层，OIT／分段／EDL 目标仍归各自组件。帧末清空借用深度引用，临时 hook 和可见性在 finally 恢复；销毁时先解除管线借用，再释放实体与标注组件。
- Three.js 当前输出合成器没有异常 finally。内部 effect 边界记录首个异常、跳过后续阶段，让输出层正常退出，再由帧入口抛出；不修改上游实现。嵌套管线帧在改动外层状态之前拒绝。

公开 API、既有 transmission、OIT／Spark／Takram 算法、八层分段与远端近似均保持。新接口只属于内部实现，不建立通用 Render Graph。

## 工程验证与边界

- `pnpm type-check` 通过；105 个测试文件、393 项测试通过。新增检查覆盖失效资源、跨 Viewer 隔离、显式深度与颜色交换、异常解绑、实体单独入口、异常恢复和嵌套帧拒绝。
- `pnpm build` 通过，产物约 643.44 kB／gzip 156.47 kB（十进制），4 项 dist API 消费检查通过；相关验证 fixture 的严格 tsc 通过。
- 示例初始构建曾达到 800.70 KiB gzip，超出原 800 KiB 限额。runner 通用样式由 `?raw` 改为 `?inline`，由 Vite 处理与压缩后仍同步注入；最终示例构建已通过原预算，没有延迟必需样式或提高限额。
- 首次运动脚本误向无高斯的透明柱页面安装混合夹具，已将夹具限制为高斯入口，完整运动矩阵复跑通过。开发态一次 iframe detached 发生在重建／热更新期间，最终入口使用稳定构建产物重新检查，不将该次记录视作通过。
- 深度状态脚本最初在默认循环间手动 `render()`，让下一次 rAF 时间落在手动帧之前，触发 Clock 非负校验；改为等待正常帧后复跑，错误消失。点云等待改为实际含 `aPointSize` 的 geometry 出现，防止空内容误验收。
- 旧地平线夹具只强制刷新 TilesGroup，自有静态子瓦片不会接收 force，导致已有内容仍在原处，只有后续加载瓦片采用新变换。补上子瓦片世界矩阵刷新；新的投影检查要求移动后中心位于屏幕中心附近。冻结 LOD 的新夹具据此稳定复现全部已加载内容，原实验记录保留。
- 暂不清理 artifacts，不包含既有 A1 采样实验及 AGENTS.md、.gitignore 的独立修改。

主要复现入口：`verifyMixedTransparency.ts`、`verifyPipelineLifecycle.ts`、`verifyStageSubmission.ts` 的浏览器 fixture，以及 `examples/rendering-prototypes/verify-pipeline-compat.mjs --depth-states`、`verify-pipeline-motion.mjs --mixed`、`verify-pipeline-horizon.mjs`、`verify-pipeline-fps.mjs --mixed --clouds`。脚本前两个参数分别为服务地址与输出目录；动态导入验证 TS 的脚本使用 Vite 开发服务，最终入口／样式检查使用 examples 构建后的 preview 服务。
