# 阶段 2：云深度贡献接缝验证

> 2026-09-13。有限选型实验，**未修改生产云积分器，未完成云／混合透明遮挡**。

> 同日用户后续将本版性能目标更新为 **60 FPS**，允许比原方案增加合成开销。本文此前“性能不退化”的结果只保留为历史成本证据，不再作为现行否决条件；画面差异失败和未覆盖场景仍需解决。

> **本版已停止继续执行本文实验。** 用户随后明确暂缓云穿插；此文及 JSON 仅保留证据，不再是本版完成门槛。透明物体之间的混合遮挡继续实施，性能验收已确认为 1920×1080、DPR 1、RTX 3060 Ti、60 FPS。

## 问题、对照与停止条件

要判断的最小问题：一个透明平面在云前、云后或穿云时，仅交换整张云 overlay 的前后顺序是否足够。采用原 Takram CloudsMaterial、同一帧相机／天气／阴影／jitter、原质量参数，分别以固定视空间平面深度裁剪原 raymarch；不调用额外天气、阴影或历史更新。

参考成本上限为 9 次原低分辨率 raymarch、一个临时 MRT。只回答“是否缺少物体前方的累计贡献”，不进入无限参考优化、不用该临时资源声明生产性能。一旦得到前／后排序的反例及缺失信息即停止这轮对照。

## 观察

[JSON](evidence/stage2-depth-2026-09-13.json)来自实际 `rendering-cloud-transparency` 入口，275×180 原低分辨率追踪，maxIterationCount=500、步长范围 50–1000 米。原分辨率和历史未改；本次读的是当前原始追踪附件，**没有把新的深度查询混入上游历史**。

固定 alpha=0.65，颜色 F=(0.1,0.8,1.5)，背景 B=(0.05,0.1,0.2)。用截断前缀 Cf、Tf 和整段 Ca、Ta 构造单平面参考：

`alpha * (Cf + Tf*F) + (1-alpha) * (Ca + Ta*B)`。

它复用上游每段代表深度空气透视近似，不能称为联合空气—云积分或物理真值。误差是线性 RGB 最大绝对值，用于揭示排序缺口，不是放宽后的产品阈值。

| 物体视空间深度 | 前后均含明显云贡献的像素数 | 全云在物体后最大误差 | 全云在物体前最大误差 |
| --- | ---: | ---: | ---: |
| 250 m | 0 | 0.00138 | 0.93859 |
| 1000 m | 1678 | 0.92577 | 0.93504 |
| 4000 m | 3423 | 0.93979 | 0.92265 |
| 16000 m | 6555 | 0.93979 | 0.85858 |
| 整段之后 | 0 | 0.93979 | 浮点舍入量级 |

云覆盖像素 34311。分别有正确的前端／后端控制；穿入时两种整图顺序都不成立。原实际场景[截图](evidence/stage2-cloud-scene-2026-09-13.png)也显示了后合成透明柱覆盖前景云、相邻不透明柱正常被云遮挡的差异。

临时附件分配 1,188,000 字节。9 次参考 GPU 查询约 0.077–1.717 ms，各深度成本不同；不是预热整帧性能样本，不据此估算生产预算。shader／GL 错误为 0。

## 可继续的最小接缝与边界

已经证伪“只交换整图前后”的方案；现有 frontDepth 是透射率加权代表距离，不能从它恢复上表的前缀分布。下一轮允许在**原步进不变**的实验副本中记录一个指定查询深度处的累计贡献，对照当前重复截断参考，判断是否能复用同一次天气、密度和照明采样。先限制为单平面；不直接引入通用多层 atlas、替换积分或新历史系统。

若一个查询深度成立，再检查真实 Spark／实体／普通透明的多个深度需求，以及原低分辨率追踪中细柱和显露的覆盖边界。一个前缀不等于任意深度查询；不能用单平面通过代表混合透明通过。需要增加层数、改变核心算法或历史时，依照主计划记录必要性、成本与更小方案失败证据，再审查具体差异。

脚本：[verifyCloudDepthQueries.ts](../../examples/rendering-prototypes/verifyCloudDepthQueries.ts)、[verify-cloud-depth-queries.mjs](../../examples/rendering-prototypes/verify-cloud-depth-queries.mjs)。参考临时资源在 finally 释放，深度输入、renderTarget、toneMapping 均恢复。

## 单查询记录实验：成立范围与未解决差异

以 `--capture-prefix` 运行第二个有限对照：暂时去除代表深度空气透视及独立 haze，隔离原纯云步进的累计 RGB／alpha，在原循环中记录一个查询深度前的已有累计值。不改变步长、密度、天气、照明或终止条件；多一次 RGBA16F 输出，无额外密度采样。临时副本结束后恢复原 fragmentShader、defines 和 uniforms。

新增写出首先未通过“与未插桩 shader 的整段输出完全不变”检查，最大差值 1。这项失败没有撤销：只增加附件但不写循环值时差值为 0，恢复原 shader 时也为 0。等价有理化球面 UV 表达式没有消除差异，见[反证](evidence/stage2-prefix-uv-control-2026-09-13.json)；没有因此把旧 A1 数值改写带入生产。编译后浮点运算及自适应采样是待核查方向，尚未确认具体根因。

随后增加独立问题的对照：**保持同一个编译后的插桩 shader**，比较整段步进记录的前缀与同 shader 截断到查询深度的颜色输出。[最终记录](evidence/stage2-prefix-paired-2026-09-13.json)中 250–32000 米及无限远共 9 项 `sameProgramMax=0`，同时保留 `fullMax=1` 的原 shader 差异。背景深度 1 的含义是“不截断”，已修复测试最初误当 cameraFar 的问题。

这一轮含诊断控制共 29 次参考 draw，旧参考 MRT 1,188,000 字节，带前缀的临时 MRT 1,584,000 字节；不是生产资源预算，也没有性能通过结论。早期 JSON 的 `extraReferenceDraws=18` 未计新增诊断控制，不能使用该旧字段估计成本。

结论仅为：单个指定深度的累计贡献可以从同一次原步进中记录，并匹配同程序截断参考。原云画面质量、时序与低分辨率查询有效域、多深度和混合透明仍待验证，**未采用该实验替换生产路径**。下一步应先回答整段输出差异在已解析采样／实际重建画面中的来源和影响，再决定是否扩大接入。

## 原生 resolve/history 对照及本候选停止点

将记录改为穿过查询深度时只写一次，避免每次积分都写前缀。修正主循环插桩位置后，[9 个深度的同程序对照](evidence/stage2-prefix-once-2026-09-13.json)仍全部差值 0；对原 shader 的整段最大差值仍为 1。`artifacts/stage2-prefix-once` 是误插到次级光照循环的失败脚本，含 GL 错误，不能使用其中的差值结果；此错误已修正。

随后通过原 CloudsPass 的 resolve/history 运行 original／prefix／prefix／original 四块，每块预热 64 帧、测量 32 帧，平均其中 4 帧的 RGBA16F 重建结果。固定相机、near/far、时钟、风速和天气偏移；等待全部云纹理就绪；额外复制实际不透明深度，排除地球 LOD 改变云裁剪输入。原质量和原时间重建保留。该深度副本 3,168,000 字节只属于诊断，不是生产资源。

普通程序缓存下，original 自身重复 alpha 最大差值约 0.37054，因此不能直接把 AB 差值当作候选误差。对照为每块销毁并重建 currentMaterial 的 GPU 程序（不释放纹理）后，[记录](evidence/stage2-prefix-resolved-2026-09-13.json)变为：

| 比较 | RGBA 最大差值 | 平均差值 |
| --- | ---: | ---: |
| original 自重复 | 0.001831 | 0.000002428 |
| prefix 自重复 | 0.000732 | 0.000000943 |
| original 与 prefix | 0.370361 | 0.000594795 |

没有 non-finite／shader／GL 错误，但候选局部最大差值远大于自身重复误差，不能用很小的全图平均值签收。重建程序能改变原方案重复误差是观察，不足以证明 Three.js 缓存或云公式存在生产 bug；本轮没有修改上游缓存机制。

同轮整帧 GPU p50：original 两块约 3.12／2.89 ms，prefix 两块约 3.70／3.24 ms；新增低分辨率前缀附件 396,000 字节。只记录一个未消费的前缀已经有额外成本，尚无同质量性能不退化证据，更不能外推多前缀成本。

本候选在此停止扩大：**信息可提取，但原云形态兼容和成本未通过**。不继续为插桩差异无限扩展球面数值改写、云积分器或历史系统。

## 替代路线的局部复评

现有证据只排除了整张 overlay 排序与当前循环记录实现，不足以排除所有有限扩展。下一项更小的独立比较可以保持原云 shader 文本和原整段输出不变，使用现有 depth 输入另外查询透明覆盖区域的截断贡献；通过屏幕覆盖区域限制额外 raymarch，而非修改其循环。

- 必要性：整图前后顺序已有穿云反例，物体前方累计贡献确实缺失。
- 差异：原主云输出／历史完全保留；额外查询需要独立目标和有效区域。初次仅对一个已知透明平面测量，不扩成多层 atlas。
- 成本风险：重复密度／照明采样是真实成本，不能称为免费复用；大面积透明和多层重叠可能直接不可行。先测原 shader 的附加查询成本及覆盖面积关系，再决定是否值得接入。
- 停止条件（按用户后续确认更新）：若完整实际用例不能达到 60 FPS，或必须降低云质量、减少场景内容才能达标，则否决此路线。允许新增成本不被原编排节省完全抵消；原方案差值用于解释成本，不再作为必须为负的门槛。
- 不预先承诺：新前缀的时序处理、真实透明深度、Spark／普通透明／OIT 交叉仍需单独选择与验证。这个局部复评没有把云阶段宣布完成，也不授权替换成新的云渲染器。

第一轮[区域查询成本](evidence/stage2-query-cost-2026-09-13.json)已经运行：原 shader 文本不变，4000 米查询深度，1100×720 整帧、275×180 查询目标，每块预热／采样各 30 帧，顺序为 0／1⁄16／1⁄4／全屏再反向。无查询两块 GPU p50 为 2.934／2.657 ms，1⁄16 为 3.294／2.915 ms，1⁄4 为 2.913／2.945 ms，全屏为 3.269／3.255 ms。局部面积与时间未呈稳定单调关系，存在调度漂移，不能据此宣布局部查询免费或性能通过。

这一轮包含额外原 currentPass 的 draw，临时 MRT 1,188,000 字节；不包含透明深度绘制、前缀历史或最终合成。它证明原 shader 查询可以独立执行且无 GL 错误，尚不足以选定生产路线。后续比较应使用帧内阶段计时和交错配对隔离新增成本，避免再用有漂移的块均值做结论。
