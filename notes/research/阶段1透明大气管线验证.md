# 阶段 1：透明大气管线验证

> 2026-09-13，开发分支上的阶段 1 历史实现和观测。**本文不是整项管线计划验收记录**；当时未完成的工作与旧测量范围保留供追溯。

> 后续实施已统一云／大气开关下的提交阶段，并完成最多八层的混合透明、曲壳、运动、地平线和最终工程检查；1080p 实际混合场景平均 76.33 FPS。本文无云数据保留其原测量范围；最终范围与证据见[阶段 2 实现](阶段2混合透明分段实现与验证.md)。云穿插已由用户暂缓。

## 已实现的范围

`PostProcessingManager` 仍是 WebGL effects 所有者。无活动云且开启大气时，内部 `SceneSubmission` 借用 Three.js 主目标及硬件深度，将原列表拆成不透明／transmission、大气、普通透明／Spark；实体 OIT 使用同一个 `TransparentAtmosphere` LUT 适配器。输出转换仍由 WebGLOutput 执行，没有新增公开 API。

- 使用 Three r184 `renderLists.get/finish` 接缝，保留原生分类、材质组、排序及 transmission 预绘制；不改对象层或材质 visible。
- 外层负责矩阵、阴影和场景回调；内层阶段禁止重复这些动作，异常路径恢复状态。透明列表复制 RenderItem，避免内层列表复用以及应用回调修改材质分类导致漏画。
- 借用原不透明深度附件。颜色发生交换时只复制颜色回原目标，不分配独立透明 RT。
- 透明内容在 alpha 混合前使用自身位置求空气透视。普通网格逐片元求值；Spark 默认在高斯中心求值，保留其解码、LOD、排序和显示色补偿。
- light-source 模式且没有特殊点云法线 mask 时，跳过不需要的 normal pass。post-process 光照或点云 mask 保留该 pass。普通透明复用原太阳／天空 irradiance、albedoScale 和昼夜参数；局部光照对象保留已着色 radiance。
- 有活动云时保留旧路径，未把无云修复宣传成云遮挡修复。

## 合同与数值对照

[合同证据](evidence/stage1-contracts-2026-09-13.json)覆盖原生对照、动态回调、transmission，以及颜色交换／不交换。新提交方式与原生图像最大差值为 0，回调／阴影次数一致。旧的 material.visible 分组原型在动态分类时最大差值 68 或 143，不能作为生产方案。

[采样证据](evidence/stage1-sampling-2026-09-13.json)固定相机、真实高斯可见规模和截图时点。阈值在观察结果前定为每个显示通道 2 个 8-bit 等级；只用于中心求值对该静态片元参考的替代判断。透明柱差值 0、实体 1、真实高斯 1，高斯重复参考差值 0；不构成所有运动／轮廓的误差保证。曾尝试普通网格顶点求值，实体最大差值 27、31269 个通道超出 2，已撤回，保留[失败证据](evidence/stage1-rejected-vertex-2026-09-13.json)。

[生命周期记录](evidence/stage1-lifecycle-2026-09-13.json)中，两个独立 Viewer 的午间／日落／夜间 normal-pass 对照差值为 0；24 个尺寸、云、大气和 SMAA 组合没有 GL 错误，销毁一个 Viewer 后另一个继续渲染。随后修复共享材质重复叠加 hook，并通过[共用材质的同组回归](evidence/stage1-shared-lifecycle-2026-09-13.json)。材质只保留一个组合 hook，切换 Viewer 时恢复旧 hook；GPU program/uniforms 仍归各 renderer 缓存所有。

[光照对照](evidence/stage1-lighting-2026-09-13.json)以 alpha=1 的透明 Basic 面对比同位置不透明面。post-process／light-source、local／globe、12／18／0 时共 12 组最大显示差值为 0–1，均没有超出预定 2 等级阈值。此对照验证自身光照与空气透视的一致性，不覆盖所有自定义着色器或半透明混合排序。该脚本的控制台记录另有一个未记 URL 的资源 404，不将此条记录视作完整资源加载验收；shader／GL 检查没有错误。

[自定义 GLSL 对照](evidence/stage1-custom-shader-2026-09-13.json)覆盖 RawShaderMaterial 的 GLSL3 命名颜色输出、条件提前 return 和 main 之后的辅助函数。6 个 light-source 用例最大显示差值为 1，无 shader／GL 错误。适配器在 main 内插入颜色处理并保留条件 return 的控制流；这不代表任意自定义 MRT 或自定义光照着色器已获支持。

## 实际入口与成本

[恢复锁定依赖后的记录](evidence/stage1-pipeline-2026-09-13.json)覆盖独立页和 Sandcastle 的透明柱、实体、真实 `gaussian-splat-3d-tiles`。均未报告 shader／GL 错误或资源失败。截图验证了固定视角的可见内容，尚不能关闭地平线／山体、运动和混合排序验收。

RTX 3060 Ti / ANGLE D3D11 / Chrome，独立页 1100×720、DPR 1。固定数据、时钟及无云状态，交错 native／submission／aerial，每块预热 30、采样 30 帧，保留全部块和异常；GPU disjoint 只记无效。native 是原主场景 + 原 normal pass；submission 只改编排，aerial 加透明自身空气透视并省去无用 normal pass。

该轮真实高斯 native 各块 GPU p50 为 4.212–4.560 ms，完整无云候选为 3.478–3.506 ms。实体各块明显受调度漂移影响，不宣布精确相等或全面通过。另存[连续负载对照](evidence/stage1-continuous-2026-09-13.json)，与帧率限制测量分开报告。计时只含 `Viewer.render`，不含示例外部的 tileset.update，不等于应用完整帧耗时。

测量曾发现 symbol 后合成会每帧恢复 manager.activeEffects，导致只在块开头安装 native 的早期数据实际测到候选。最终脚本在**每帧**安装对照链并断言 opaque 阶段进入次数；`artifacts/stage1`、`stage1-r2` 等早期 native 性能数据废弃，不得作为优化收益证据。

## 当时的工程结果与待办快照

- `pnpm install --frozen-lockfile --force` 恢复已配置但本机安装内容缺失的高斯插件补丁。修复后空可见集／排序等待期两个回归通过；新服务使用独立 Vite cache 并强制 optimize。未修改补丁或依赖版本。
- 当前全量测试曾以 103 个文件、388 项通过；最新源码及验证 fixture 严格类型检查、18 项管线聚焦测试、7 项 runner 绑定测试均通过。最新库构建及 4 项 dist API 消费测试通过，`dist/index.js` 为 626.24 kB / gzip 152.21 kB（十进制）。
- 构建前只移除 TS 解析器识别的运行时 JSDoc，保留源位置、许可证及 pure 标记；独立生成的声明文件保留双语文档。没有提高预算。
- 示例生产构建最初 runner gzip 803.12 KiB 超过既有 800 KiB。将 Leva 样式、遗留面板和位置读数 helper 按实际绑定加载后，最新 `pnpm build:examples` 通过原预算。生产预览的六入口复查没有 shader／GL 或资源失败，见[记录](evidence/stage1-production-2026-09-13.json)；其中 2 帧 GPU 值仅供执行诊断，不作性能统计。
- 已补实际 WebGPU 基础页、symbol、point-cloud-3d-tiles 的独立页与 Sandcastle 检查。分别确认实际 WebGPU 后端、可见图标／文本、真实点云与 EDL；无 GL／device 错误及资源失败，见 [WebGPU](evidence/stage3-webgpu-2026-09-13.json)和[标注／点云](evidence/stage3-symbol-point-cloud-2026-09-13.json)。
- [相机运动记录](evidence/stage3-motion-2026-09-13.json)覆盖透明柱和真实高斯的独立页／Sandcastle，各 4 个连续转向端点，无 shader／GL 错误。透明柱跨地平线与白墙遮挡、绿色高亮轮廓已目视确认。真实高斯主体保持可见；Sandcastle 起始／返回截图仍有背景点状过渡。[原主场景管线对照](evidence/stage3-motion-native-2026-09-13.json)也出现背景点状过渡，故不能直接归因新编排，但尚未定位具体来源，不宣称完整时序验收通过。该转向测试也没有覆盖真实高斯跨地平线和山体显露。
