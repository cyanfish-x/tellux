# 前置依赖打包策略备忘

> 2026-09-06 复核范围：核对 package.json、peerDependencyExternal 与 vite.config.ts；区分项目 external 决策与双实例可能造成的风险，没有重新测量包体积。


本文记录 tellux 对前置依赖（three、3d-tiles-renderer、takram 系列等）打包策略的评审结论，用于回看与决策对齐。

## 结论

前置依赖**不应参与打包**。维持当前 `external` + `peerDependencies` 设计，由消费者自行提供这些依赖。

适用场景：

- 评审或调整 `vite.config.ts` 的 `external` 列表。
- 变更 `package.json` 的 `dependencies` / `peerDependencies` / `devDependencies` 分类。
- 评估是否把某个第三方依赖打进 lib 产物。
- 处理 three 单例、双实例运行时报错或第三方类型不兼容问题。

## 当前打包策略现状

`vite.config.ts` 通过包根 predicate 把所有核心前置依赖声明为 `external`（产物里只保留 `import` 引用，不内联实现）：

```ts
export const EXTERNAL_PACKAGE_ROOTS = [
  '3d-tiles-renderer',
  '@takram/three-atmosphere',
  '@takram/three-clouds',
  '@takram/three-geospatial',
  '@takram/three-geospatial-effects',
  'postprocessing',
  'three'
]

export function isPeerDependencyExternal(id: string) {
  return EXTERNAL_PACKAGE_ROOTS.some(
    (packageRoot) => id === packageRoot || id.startsWith(`${packageRoot}/`)
  )
}
```

因此 `three/webgpu`、`three/tsl`、`three/addons/*`、`3d-tiles-renderer/core/plugins` 等当前及未来子路径会自动遵守同一边界，无需逐项补名单。构建插件还会检查 Rollup chunk 的 module id；如果上述 peer 的实现进入产物，构建会直接失败。

产物形态：

- 纯 ESM：`formats: ['es']`，无 CJS / UMD。
- 多入口：`index` + `assets`，输出到 `dist/`。
- `src/index.ts`、`src/assets.ts` 之外的代码（`actions/` 部署脚本）不进入 lib 产物。

依赖分类与 `package.json` 一致：

- 7 个核心前置依赖根全部声明为 `peerDependencies`，且所有子路径都被 `external` 覆盖。
- `@mapbox/vector-tile` / `pbf` 标记为 `peerDependenciesMeta.optional`，且不在 `external` 中；若未来进入库入口依赖图，允许由 Tellux 打包，目前它们由 `3d-tiles-renderer` 自身依赖链提供。

## 为什么不能打进包

### 1. 保持宿主与引擎使用同一份 Three.js

- 多份 Three.js 可能导致实例身份、材质节点、类型与插件兼容问题，但不是所有对象传递都会立刻崩溃。项目选择 peer + external 来维持可预期的互操作边界，不把风险夸大为语言层面的“必须唯一”。

### 2. 公开契约包含第三方类型，版本需与宿主对齐

`src/index.ts` → `src/Viewer.ts` 的公开类型表面包含：

- 来自 three / three/webgpu：`TelluxRenderer` / `TelluxWebGLRenderer` / `TelluxWebGPURenderer`（底层是 three renderer），`FlyToTargetTarget` 里的 `THREE.Object3D`。
- 来自 3d-tiles-renderer：`TilesRenderer`（出现在 `TilesetLayer.tileset`、拾取结果类型）、`GlobeControls`。

用户写 TypeScript 时会 `import type` 这些类型，**类型实例必须与用户自己装的版本对齐**。类型与运行时版本应一起核查；打包依赖本身不必然导致声明冲突。

### 3. takram 全家桶 / postprocessing / 3d-tiles-renderer 自身 `peerDependencies.three`

- `3d-tiles-renderer`、`postprocessing`、4 个 `@takram/*`自身内部都直接 `import 'three'`，运行时必须拿到宿主的**同一个** three 实例。
- 将这些库内联不必然复制 Three（仍可 external Three），但会扩大 Tellux 的产物与升级边界；本项目已选择七个核心包根整体 external。

### 4. Shader 资产与依赖图也计入包体成本

- takram 包的 GLSL 被**内联打包**进它自己的 `shared*.js` / `webgpu.js`（具体大小随安装版本变化，本次未重新构建测量）。
- 依赖链互锁：`three-clouds` → `three-atmosphere` + `three-geospatial`；`three-atmosphere` → `three-geospatial` + `astronomy-engine`。
- 即便 takram 声明 `sideEffects: false`，因 GLSL 内联 + 互锁依赖 + 共享 three 实例，实际 tree-shake 收益应由依赖图与构建测量判断，不能仅从 shader 内联推断固定收益。当前 external 策略将这部分成本明确留在宿主依赖图。

## 依赖分类对照表

| 依赖 | 当前归属 | 是否应打包 | 理由 |
|---|---|---|---|
| `three`（含所有子路径） | peer + external | ❌ | 宿主互操作与版本一致性；公开 API re-export 类型；下游库均 peer 依赖它 |
| `3d-tiles-renderer`（含所有子路径） | peer + external | ❌ | 全局单例；公开 API re-export `TilesRenderer`/`GlobeControls` |
| `@takram/*`（atmosphere / clouds / geospatial / geospatial-effects） | peer + external | ❌ | 内部直接 `import 'three'`；GLSL 大体积；依赖链互锁 |
| `postprocessing` | peer + external | ❌ | three 的 postprocessing 库，绑定宿主 renderer |
| `@mapbox/vector-tile` / `pbf` | optional peer，允许打包 | ✅ 可接受 | 体积小；当前由 3d-tiles-renderer 依赖链提供 |
| `@mapbox/tiny-sdf` / `three-mesh-bvh` | runtime dependency，已打包 | ✅ | Tellux 运行时实现直接使用 |
| `@dgreenheck/ez-tree` | devDependency | — | 仅 examples 使用 |
| `dotenv` / `tencentcloud-sdk-nodejs-cdn` | devDependency | — | 仅 `actions/` 部署脚本使用 |

## 工具侧依赖边界

`dotenv`、`tencentcloud-sdk-nodejs-cdn` 仅用于 `actions/` 部署脚本，`@dgreenheck/ez-tree` 仅用于 examples。三者均位于 devDependencies，不会成为 `tellux` 消费者的运行时安装负担。

## 相关文件索引

- `package.json`：`peerDependencies` / `peerDependenciesMeta` 依据。
- `src/build/peerDependencyExternal.ts`：external 包根、specifier 判定和构建模块识别。
- `vite.config.ts`：external predicate、构建期 peer 内联 assertion、`build.lib` 与 `optimizeDeps.include`。
- `src/index.ts` → `src/Viewer.ts`：公开 barrel export，re-export third-party 类型。
- `src/rendering/RendererAdapter.ts`：`TelluxRenderer` = three renderer。
- `src/rendering/AtmosphereManager.ts` / `WebGPUAtmosphereManager.ts` / `PostProcessingManager.ts` / `AtmosphereTextureLoader.ts`：takram + postprocessing 使用点。
- `examples/`：部分高级示例会直接引入 `three`、`3d-tiles-renderer` 或示例专用依赖；这些依赖保留在 devDependencies，不进入发布包运行时依赖。
