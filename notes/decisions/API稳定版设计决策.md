## 领域边界为什么这样划分

| 已采纳选择 | 理由与接受的代价 |
| --- | --- |
| `overlays`、`tilesets`、`models`、`hism` 独立集合 | `layers` 容易被理解成所有 GIS 图层；`imagery` 又不能清楚覆盖 MVT / GeoJSON。overlay 不收进 globe，避免把未来场景 tileset 叠加能力锁死在路径上。既有 ImageryLayer 类型名保留，避免只有命名收益的扩散 |
| terrain 使用 `set` / `clear` | 地形是单例，集合动词会虚构多份地形；属性赋值又隐藏异步副作用并缺少操作参数扩展位 |
| `globe` 替代裸球 / 地形的 `tileset` 出口 | 公共领域对象与场景 3D Tiles 集合分开，集中管理显隐和 ellipsoid |
| renderer 为门面，原生对象统一 `.raw` | resolutionScale 等字段需要联动 viewport、实体与瓦片分辨率；直接修改原生对象不能复现全部托管副作用。保留互操作出口，不采用 Proxy 全面拦截 |
| `postProcess` 位于 Viewer 顶层 | 后处理控制输出图，不属于 Scene 的 Three.js 场景状态；初始化与运行时用同一路径 |
| `highlighter` 同时持有操作与 outline / overlay 样式 | 0.2 将操作挂 `highlight`、样式挂 `scene.highlight`，导致一项能力分裂；由一个领域对象表达选择状态与风格 |

`.raw` 是有边界的互操作出口，不保证绕过门面修改托管字段后依然同步。原生对象的类型不意味着其全部属性都由应用独立拥有，托管清单应从对应公开 JSDoc 查。

## 数据与调用形状

- 经纬度使用 `LonLat*` 普通对象 / tuple，门面与资源句柄使用类。坐标没有独立身份和生命周期，增加构造器会损害字面量、JSON 与结构类型互操作；需要 Three 数学时通过坐标转换入口转为 `Vector3` / `Matrix4`。
- 无高度与有高度的类型分开，不能把缺省高度暗中补成 0；相机初始化目的地需要高度，运行时无高度目的地可保持当前高度。
- 采样结果只返回高度或 `undefined`，不重复返回输入经纬度。单点与批量各自有重载；同步批量应与逐点结果逐元素相等。异步批量共享准备和加载成本，不从历史测速推断所有场景的固定倍数。
- 3D Tiles 数据源放进 `{ source }`，图层 id / show 留在图层层级。来源判别与图层显示不混为一个对象的杂项字段。
- 描边使用存在即开启的可选子对象，宽度默认非零；避免存在对象却仍因隐含零值不可见。实体图形字段的具体更名表留在迁移指南。
- 同一领域初始化与运行时同构，不要求不同语义的数据全部机械同名；例如 terrain 单例与资源集合、实体不同几何的尺寸字段可以不同。

## 真正的公开契约边界

导出类的 public 成员会进入 `.d.ts`，没有单独从 barrel 导出不等于内部。2026-09-06 核对 `tsconfig.types.json` 仍未启用 `stripInternal`；`@internal` 注释本身不能移除声明，更不能提供运行时封装。

需要收口时先处理可达性：私有成员、构造注入或包内 WeakMap 侧表各有适用范围。只依赖 `@internal` + 声明裁剪时还需要产物断言，不能以源码类型测试代替。移除任何已有可访问成员都是兼容性变更，名字带 Impl 并不能豁免。

消费者实际看到的是 `package.json` 的 exports、`dist/index.d.ts` 与 assets 声明。源 barrel 检查与构建产物检查应区分；当前 `package.json` 的 build 已在生成声明后运行 `src/test/distApiSurface.test.ts`。单独执行测试而无 dist 时，该测试会 skip，因此源码测试通过不能代替新构建产物验收。本次未重新构建，不能给出产物合格结论。

## 没有随这次稳定窗口强行扩展的部分

只为外观统一而缺少用户收益的更名不继续扩大。Clock 不为了模仿其他引擎而补循环范围或数据驱动，Timeline 的民用时间范围与场景时钟职责分开，见 [Clock 决策](Clock统一场景时钟.md)。事件便利字段和具体几何尺寸语义不因追求完全去重而删除。

后续新增能力通常可以增量扩展，不能把原稿中的候选方案、beta 节奏或批次顺序升级为永久项目规则。当前硬约束仍由 `AGENTS.md` 和具体已采纳决策维护。
